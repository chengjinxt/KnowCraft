# Windows 凭据管理器知识卡提示词

## 统一视觉规范

- 3:4 竖版中文知识卡，浅暖灰纸张背景，深海军蓝、青绿色和珊瑚红作为主色。
- 扁平矢量信息图，轻微纸张纹理和柔和阴影，圆角卡片、粗描边、清晰箭头。
- 中文标题必须醒目，正文使用简体中文；代码、API 和凭据类型保持英文原文。
- 信息层级清晰，留白充足，适合手机阅读；不使用真实账号、IP、路径、密码或内部目标名。
- 所有关键文字都直接绘制在图片中，避免装饰性乱码和多余小字。

## 参考关系

- 第 1 张参考项目既有卡片 `assets/20261029_01_git-pull-merge-cards/01-why-pull-creates-merge.png` 的版式与质感。
- 第 2～5 张依次参考上一张已生成卡片，保持同一套视觉语言。

## 01-domain-vs-generic.png

> 生成一张 3:4 竖版中文知识卡，标题必须准确写成“Windows 凭据不是一种”。副标题写“Domain Password（域密码）≠ Generic Credential（普通凭据）”。中部采用左右对比布局：左侧珊瑚红卡片标题“Domain Password”，标注“CRED_TYPE_DOMAIN_PASSWORD = 2”，用 Windows/域网络与钥匙图标表示，正文写“服务于 NTLM、Kerberos、Negotiate 等系统身份验证”；右侧青绿色卡片标题“Generic Credential”，标注“CRED_TYPE_GENERIC = 1”，用应用程序保险箱与钥匙图标表示，正文写“保存应用自行定义的业务口令”。中间用醒目的不等号分隔。底部结论条必须写“目标名相同，类型也必须匹配”。使用浅暖灰纸张背景、深海军蓝粗标题、扁平矢量信息图、圆角卡片、轻微纸张纹理与柔和阴影。文字必须清晰、简体中文正确，不出现真实账号、路径、密码、IP 或内部目标名。

## 02-create-generic-in-ui.png

> 延续上一张的浅暖灰、深海军蓝、青绿色、珊瑚红扁平矢量风格，生成 3:4 竖版中文知识卡。标题必须准确写“界面里怎样建 Generic？”。主体画一个简化的 Windows“凭据管理器”页面，从上到下清晰分成三段：“Windows 凭据”“基于证书的凭据”“普通凭据”。在页面右侧分别出现按钮，上方按钮写“添加 Windows 凭据”，底部普通凭据区域的按钮写“添加普通凭据”。用向下滚动箭头和青绿色高亮框强调：必须向下滚动到“普通凭据”，点击“添加普通凭据”。用珊瑚红叉号标注上方“添加 Windows 凭据”，旁边小注“这会创建 Domain Password”。底部结论条写“要的是 Generic，就选普通凭据”。不要出现真实服务器地址、用户名、密码、路径或内部名称；界面文字必须清晰准确。

## 03-create-and-check-with-cmdkey.png

> 延续同系列 3:4 竖版知识卡风格，标题写“命令行也能安全创建”。上半部画一个深海军蓝终端窗口，必须逐字清晰展示两行命令：`cmdkey /generic:<凭据目标> /user:<工具用户> /pass` 和 `cmdkey /list:<凭据目标>`。第一行旁边用青绿色对话气泡写“/pass 不带值：交互输入”，并画键盘与遮罩圆点，表示口令不会进入命令历史。第二行下面画检查结果卡片，突出 `Type: Generic`。右下角用珊瑚红警告框写“不要使用 /pass:<明文密码>”，配命令历史和放大镜图标。底部结论条写“创建看 /generic，检查看 Type: Generic”。使用浅暖灰背景、扁平矢量图标、圆角模块和清晰代码字体；不出现真实目标名、账号或密码。

## 04-controlled-credential-injection.png

> 延续同系列视觉，生成 3:4 竖版中文知识卡。标题写“为什么不长期放环境变量？”。上半部画两个并排进程窗口：左侧“旧进程”保留旧环境值，右侧“新进程”才继承更新值；中间用断开的刷新箭头表示“修改用户环境变量，不会自动更新已运行进程”。下半部画一条清晰安全链路：绿色保险箱“凭据管理器（Generic）” → API 节点“CredReadW” → 深蓝启动器“受控启动器” → 单个青绿色窗口“目标子进程”。箭头旁写“只注入本次所需口令”，目标子进程下方写“读取后从自身环境映射移除”。旁边用珊瑚红叉掉一排无关子进程和“打印全部环境变量”的终端。底部结论条写“缩小暴露范围，不等于跨进程保险箱”。图标简洁、箭头清晰，不出现真实变量名、密码、路径或内部工具名。

## 05-troubleshoot-wrong-password.png

> 延续同系列 3:4 竖版中文知识卡，标题写“Wrong password 不一定是密码错”。中部做三层漏斗或三步排查路线：第一层青绿色卡片“凭据层”，检查“目标名 / 用户 / Type: Generic”；第二层深蓝卡片“输入通道层”，检查“程序是否真的收到口令”，旁边画标准输入箭头和问号；第三层珊瑚色卡片“格式层”，列出“ZipCrypto / AES ZIP / 7z / RAR”，强调不同格式能力不同。三层汇聚到一个停止标志，文字写“日志无法安全解密：停止分析”。旁边再写“不要把明文口令拼进命令行”“不要用源码猜测替代现场证据”。底部结论条写“先分层定位，再决定修复”。保持浅暖灰纸张背景、扁平矢量图标、圆角模块、强对比和手机可读性，不出现任何真实密码、账号、IP、路径或内部名称。
