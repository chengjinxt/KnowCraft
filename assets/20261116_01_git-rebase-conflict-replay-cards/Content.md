# Rebase 冲突会再来吗

## 先说结论

解决一次 Rebase（变基）冲突，只代表当前这次重放完成。解决结果会进入新提交 `A'`；以后是否再冲突，取决于新的远端提交是否和本地提交改到同一片代码。

## Git 重放什么

`git pull --rebase` 先 Fetch（获取）远端更新，再把本地独有提交的改动 Replay（重放）到新基准后。旧提交 `A` 不会原地移动，而会生成 `A'`，所以提交哈希会改变。

## 什么时候不会

远端不变时，再次执行通常显示 `Already up to date`。本地提交已经 push，之后没有新的本地独有提交时，拉取通常只需 Fast-forward（快进），无需重放。

## 什么时候还会

若远端新增 `R`，本地仍有未推送 `A`，且二者修改同一区域，`A` 重放为 `A'` 时仍可能出现 Conflict（冲突）。先 `git fetch`，再看 ahead / behind，确认后再 rebase。
