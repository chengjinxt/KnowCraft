# ImageGen 最终提示词

以下 8 张卡片均使用 Codex 内置 `imagegen` 生成，分类为 `scientific-educational`。共同要求：原创中文信息图、`3:4` 竖版、完全不透明浅米白背景、深海军蓝高对比标题、圆角信息块、手机端易读；不使用真实品牌、型号、SSID、MAC 地址、账户、订阅链接、Logo、水印或页码。

## 01 — 光猫、路由器与智能网关

```text
Primary request: 面向普通家庭用户解释“家里的上网设备到底是光猫还是路由器”。

Text (verbatim):
"家里上网的盒子：光猫还是路由器？"
"结论：能发 Wi-Fi、能插网线，并不能单独证明它是哪一种。"
"光猫"
"ONT (Optical Network Terminal，光网络终端)"
"把运营商的光信号转换成以太网数据"
"关键线索：直接接入光纤，常见接口标有 PON 或 OPTICAL"
"路由器"
"Router（路由器）"
"连接家庭网与上级网络，负责 DHCP、NAT、Wi-Fi 和多个网口"
"关键线索：通常只有 WAN、LAN 和 POWER"
"二合一智能网关"
"Optical Gateway（光网关）"
"同一台设备同时完成光信号转换与家庭路由"
"所以它既像光猫，也像路由器"
"判断口诀"
"先看进线：光纤进设备 → 有光猫功能"
"再看接口：只有 WAN / LAN → 更像独立路由器"
"最后看模式：设备可能工作在路由、AP 或 Mesh 模式"

Constraints: 明确 Wi-Fi 与网口不足以判断；ONT、PON、OPTICAL、WAN、LAN、DHCP、NAT、AP、Mesh 大小写准确。
```

## 02 — 根据接口与接线判断角色

```text
Primary request: 教普通用户通过背面接口和实际进线判断设备角色，强调“接口标签 + 接线方式 + 工作模式”一起看。

Text (verbatim):
"看接口，3 秒判断设备角色"
"① 光纤直接进设备"
"细光纤 → PON / OPTICAL"
"这是 ONT (Optical Network Terminal，光网络终端)"
"它至少具备光猫功能"
"② 网线从上级设备接入"
"上级设备 → WAN"
"这是 Router（路由器）的典型接法"
"它负责把家庭网络接到上级网络"
"③ 网线接 LAN，WAN 空着"
"上级网络 → LAN"
"设备可能工作在 AP 或 Mesh 桥接模式"
"AP (Access Point，无线接入点)：主要负责提供 Wi-Fi，不一定负责路由"
"常见接口"
"PON / OPTICAL：光纤入口"
"WAN：上级网络入口"
"LAN：电脑、电视等本地设备"
"POWER：电源"
"注意"
"同一台硬件可以切换路由、AP、中继或 Mesh 模式"
"所以要同时看：接口标签 + 实际接线 + 管理后台模式"
"一句话：外壳会骗人，进线和模式更可靠。"

Constraints: 不得声称 WAN 空着就必然是 AP；清楚画出光纤与普通网线的差别。
```

## 03 — 一张 ipconfig 表里的不同角色

```text
Primary request: 用一张简化的 Windows 网络信息卡，解释 IPv4 地址、默认网关、DHCP 服务器、DNS 服务器和管理地址各自是什么。

Text (verbatim):
"一张 ipconfig 表里，谁是谁？"
"同一张表里的地址，可能代表完全不同的角色。"
"示例网络：192.168.50.0/24"
"IPv4 地址：192.168.50.23"
"默认网关：192.168.50.1"
"DHCP 服务器：192.168.50.1"
"DNS 服务器：192.168.50.1、192.0.2.53"
"管理地址：由设备配置决定"
"IPv4 (Internet Protocol version 4，互联网协议第 4 版)"
"192.168.50.23 是这台笔记本在当前局域网里的地址"
"Default Gateway（默认网关）"
"192.168.50.1 是离开当前网段时交给数据包的第一站"
"DHCP (Dynamic Host Configuration Protocol，动态主机配置协议)"
"自动分配 IP、子网掩码、网关和 DNS 等参数"
"DNS (Domain Name System，域名系统)"
"把域名解析为 IP；它可以是路由器，也可以是其他服务器"
"管理地址"
"用来打开设备后台；常与网关相同，但也可能是单独配置的地址"
"容易误解"
"默认网关不等于笔记本地址"
"DNS 地址不等于光猫地址"
"后台地址不能只靠末尾是不是 .1 来猜"
"示例地址仅用于讲解，不对应任何真实家庭设备。"

Constraints: `192.0.2.53` 只能作为文档示例地址；不得暗示末尾 `.1` 一定是路由器。
```

## 04 — 热点、二级路由与多一跳

```text
Primary request: 解释为什么经过手机热点、二级路由或多级家庭网关时会出现“多一跳”和不同网段。

Text (verbatim):
"为什么经过热点后，会多出一个 IP？"
"结论：每经过一层真正的路由，就可能进入一个新的网段。"
"笔记本"
"192.168.30.20"
"↓ Wi-Fi"
"手机热点 / 二级路由"
"网关 192.168.30.1"
"hop 1"
"↓ 上级网络"
"家庭路由器"
"网关 192.168.50.1"
"hop 2"
"↓ WAN"
"光网关"
"管理地址 192.168.1.1"
"hop 3"
"↓ 运营商公网"
"Internet（互联网）"
"NAT (Network Address Translation，网络地址转换)"
"路由器会在不同网络之间转发数据，并可能转换源地址"
"多层路由可能形成 Double NAT（双重网络地址转换）"
"普通上网通常可用，但端口映射、远程访问和部分联机可能更复杂"
"AP (Access Point，无线接入点)"
"纯 AP / 桥接只延伸同一个局域网，通常不会新增路由跳数"
"怎么看路径？"
"ipconfig /all：只告诉你当前的第一跳网关"
"tracert -d 1.1.1.1：依次显示经过的路由节点"
"示例地址仅用于讲解，不对应任何真实设备。"

Constraints: 不能说每一跳都一定执行 NAT；准确区分 Router 路由与 AP 桥接。
```

## 05 — 用命令画出家庭网络路径

```text
Primary request: 教普通 Windows 用户用四条只读命令判断“电脑连了谁、第一跳是谁、上级设备在哪里、后台页面属于谁”。

Text (verbatim):
"4 条命令，画出家庭网络路径"
"目标：确认当前 Wi-Fi、第一跳网关、上级设备和管理页面"
"① 看本机网络参数"
"ipconfig /all"
"重点读：IPv4 地址、默认网关、DHCP 服务器、DNS 服务器"
"默认网关就是当前数据离开本地网段的第一站"
"② 确认实际连接的 Wi-Fi"
"netsh wlan show interfaces"
"SSID：无线网络名称"
"BSSID：当前无线接入点的 MAC 地址"
"同名 Wi-Fi 可能来自不同 AP，BSSID 能帮助区分"
"③ 跟踪去往公网的路径"
"tracert -d 1.1.1.1"
"示例："
"1  192.168.50.1   当前路由器"
"2  192.168.1.1    可能的上级网关"
"3  公网地址        运营商网络"
"-d：不反查域名，结果更直接"
"④ 读取后台登录页标题"
"curl.exe -L http://192.168.1.1"
"如果页面显示“智能网关”，再结合 PON / OPTICAL、光状态和物理接线判断是否为光猫"
"排查原则"
"ipconfig 只显示第一跳，不会列出整条路径"
"tracert 的第二跳不一定就是光猫，也可能是另一台路由器"
"页面标题只是线索，接口与接线才能确认设备角色"
"以上地址均为示例，请替换为自己网络中实际发现的地址。"

Constraints: 四条命令逐字准确；不得把第二跳绝对判定为光猫；不得暗示 `curl` 会登录或破解设备。
```

## 06 — 读懂 arp -a

```text
Primary request: 用简化的 Windows `arp -a` 输出解释 ARP 表的意义、动态与静态条目、为什么看不到隔着路由器的光猫。

Text (verbatim):
"arp -a 到底在看什么？"
"ARP (Address Resolution Protocol，地址解析协议)"
"只在当前局域网内，把 IPv4 地址对应到 MAC 地址"
"接口：192.168.50.23"
"Internet 地址        物理地址                  类型"
"192.168.50.1       02-00-00-00-00-01      动态"
"192.168.50.25      02-00-00-00-00-25      动态"
"192.168.50.255     ff-ff-ff-ff-ff-ff      静态"
"224.0.0.251        01-00-5e-00-00-fb      静态"
"动态"
"电脑通过 ARP 查询后学习到的缓存"
"例如网关，或最近通信过的同网段设备"
"静态"
"这里常见系统预设的 Broadcast（广播）和 Multicast（组播）映射"
"不等于一台真实电脑"
"为什么看不到光猫？"
"光猫在另一个网段，并且隔着路由器"
"笔记本只需要知道第一跳网关的 MAC，后续由路由器继续转发"
"ARP 表 ≠ 在线设备完整名单"
"它只是最近解析过的邻居缓存，没出现不代表设备离线"
"看到多个“接口”怎么办？"
"每块物理或虚拟网卡各有一张表"
"先找与当前 IPv4 地址相同的那一段"
"169.254.x.x 常是链路本地或未取得 DHCP 地址的接口，可结合 ipconfig 判断"
"图中 IP 与 MAC 均为合成示例，不对应真实设备。"

Constraints: 强调 ARP 只解析同一链路上的 IPv4 到 MAC；动态不等于永久在线，静态不等于真实设备；不能把 `arp -a` 说成网络扫描器。
```

## 07 — 传统 VPN 与 FlClash

```text
Primary request: 解释为什么普通路由器后台的 PPTP/VPN 表单不能直接替代 FlClash，以及只有 Clash 订阅时应寻找什么路由器功能。

Text (verbatim):
"路由器里的 VPN，为什么不能直接替代 FlClash？"
"结论：名字都像“代理上网”，但配置格式和工作方式不是一回事。"
"传统 VPN 页面"
"VPN (Virtual Private Network，虚拟专用网络)"
"常见字段：名称、协议、服务器、用户名、密码"
"PPTP (Point-to-Point Tunneling Protocol，点对点隧道协议)"
"也可能支持 OpenVPN 或 WireGuard，取决于路由器固件"
"它需要服务商提供匹配协议的服务器与凭据"
"FlClash / Mihomo"
"Clash/Mihomo 代理客户端"
"常见输入：订阅链接、节点、代理组、分流规则"
"订阅不是 PPTP 服务器地址"
"不能把订阅链接直接填进“服务器”一栏"
"只有 Clash 订阅，应该去哪里？"
"已安装相应插件的 OpenWrt 路由器"
"→ 服务 → OpenClash / Mihomo"
"或使用旁路由、小主机作为透明网关"
"服务商提供标准 VPN 配置怎么办？"

"并且路由器明确支持同一协议，可以使用路由器的 VPN 客户端页面"
"安全提醒"
"PPTP 较旧，不建议用于新的安全部署"
"订阅链接通常包含账户令牌，不要公开或截图分享"

"一句话：传统 VPN 凭据填 VPN 页；Clash 订阅要交给 OpenClash / Mihomo。"

Constraints: 不得暗示所有路由器都能安装 OpenClash；不能把订阅链接当成 PPTP 服务器；不能宣称刷机零风险。
```

## 08 — 两个路由器下的电脑互访

```text
Primary request: 解释一个光猫后面连接两个路由器时，A 路由器下的电脑如何访问 B 路由器下的电脑，并说明默认为什么通常不通。

Text (verbatim):
"两个路由器下面的电脑，能互访吗？"
"例子：光猫 192.168.1.1"
"路由器 A：192.168.100.1"
"电脑 A：192.168.100.249"
"路由器 B：192.168.2.1"
"电脑 B：192.168.2.28"
"默认结论"
"通常不能直接访问。"
"因为 A 网段和 B 网段是两个 LAN，路由器还会做 NAT 和防火墙隔离。"
"NAT (Network Address Translation，网络地址转换)"
"把内网地址转换成上级网络看到的地址。"
"想互访，有 3 条路"
"① 改成同一个局域网"
"把其中一台路由器设为 AP / 桥接，关闭它的 DHCP。"
"最简单，但电脑地址会变成同一网段。"
"② 加静态路由"
"Static Route（静态路由）告诉路由器：去对方网段该走哪一台网关。"
"还要放行防火墙，很多家用路由器做不到完整支持。"
"③ 只开放一个服务"
"Port Forwarding（端口转发）把 B 路由器的某个端口转到电脑 B。"
"适合远程桌面、NAS、网页服务等单点访问。"
"一句话"
"想像邻居一样互访，用 AP/桥接；想保留两个网段，要静态路由；只访问一个应用，用端口转发。"
"示例地址仅用于讲解，不代表真实设备。"

Constraints: 不使用真实品牌、型号、SSID、MAC 地址、账号、订阅链接、二维码或水印；IP 地址必须与正文一致；不能暗示静态路由在所有家用路由器上都能实现；不能暗示端口转发会开放整个内网，只说明开放选定服务。
```
