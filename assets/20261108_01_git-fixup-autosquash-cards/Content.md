# 敏感提交未推送怎么修

## 先说结论

如果含敏感信息的提交只在本地、从未推送，可以用 fixup（修正提交）和 autosquash（自动折叠）重写历史。远端最终只收到脱敏后的新历史，旧提交不会作为分支历史出现。

## 它怎么做到

先创建针对旧提交的修正提交：

`git commit --fixup=<a1>`

再执行：

`git rebase -i --autosquash <a1^>`

Git 会把修正内容折入 `a1`，生成新的 `a1'`，再依次重放后续提交，形成 `a1' → a2' → a3'`。因为父提交变了，后续提交哈希也会改变。

## 安全边界

旧对象可能暂时留在本机 Reflog（引用日志）和对象库中。若敏感提交已经推送，改写历史不能抹掉他人克隆或缓存，必须立即轮换凭据，并协调清理远端历史。
