# Playwright：网页自动化的稳定链路

## 白话结论

Playwright 的核心不是“快速点击网页”，而是先确认页面状态，再定位真实元素，执行动作后继续验证结果。

## 技术要点

- `Browser Context（浏览器上下文）`：OmniPost 使用持久化 Chromium 配置保存登录状态，避免每次重新登录。
- `Locator（元素定位器）`：通过 DOM 选择器找到标题、正文编辑器、上传入口和按钮，并等待元素进入可操作状态。
- `File Chooser（文件选择器）`：监听页面触发的原生文件选择器，再用 `setFiles` 提交指定图片。
- B站编辑器会动态创建并立即移除文件输入框，因此 OmniPost 触发编辑器自身的 `insert` 事件，再接管随后出现的文件选择器。
- Markdown 正文同时写入 `text/markdown` 与 `text/html` 两种剪贴板格式，使目标编辑器保留标题、列表、链接和代码块等结构。
- 关键动作之间使用固定停顿，给动态控件、上传过程和弹窗联动留出稳定时间。
- 登录和验证码交给用户处理；公众号与 B站只保存草稿，视频号停在发表前，不自动发布。

## 稳定执行链路

```text
打开页面 → 等待稳定 → 定位元素 → 执行动作 → 验证结果
```

稳定性来自等待、状态检查和失败即停，而不是盲目重试或依赖固定屏幕坐标。
