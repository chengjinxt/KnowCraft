# 《界面修复一键恢复》核对记录

来源文件：`D:\gitea\ProjectKnowledgeBase\硬件设置组建\家庭组网\界面修复一键恢复.md`

该来源文件包含工具执行日志、任务消息和技术结论。本记录只保存技术点，并以 OpenClash `v0.47.156` 上游源码及当前路由器实测为准。

## 1. 模式切换空值

上游 `action_switch_run_mode()` 直接读取：

```lua
mode = HTTP.formvalue("run_mode")
```

随后把 `mode` 与 `fake-ip` 或 `redir-host` 拼接。如果前端没有提交 `run_mode`，Lua 会得到 `nil`。恢复脚本使用最小修补：

```lua
mode = HTTP.formvalue("run_mode") or ""
```

这保留上游函数的其余逻辑，包括同步 `@overwrite[0].en_mode`。

## 2. 状态文字宽度

旧现场在 `status.htm` 中增加了带 `oc-fix-status-width` 标记的 CSS，解决状态按钮过窄。本恢复包把 CSS 独立为 `router/status-width.patch.html`，只在标记不存在时插入。

## 3. 核心软链接

旧 `openclash.init` 快照把链接目标固定为 `/etc/openclash/core/clash_meta`，但仍然执行了删除后重建。更关键的是，它只修改了启动脚本；`small_flash_memory=1` 时，LuCI 控制器和核心更新器仍检查 `/tmp/etc/openclash/core/clash_meta`。

2026-10-01 实测出现“还未安装内核”假警报时，核心文件、进程、`utun` 和防火墙链都正常，直接原因就是三个组件的路径不一致。

新恢复脚本不复制旧快照，而是使用 `router/patch-persistent-core.lua` 对当前 `/etc/init.d/openclash`、LuCI 控制器和 `openclash_core.sh` 应用带结构校验的最小补丁，让它们都使用 `/etc/openclash/core/clash_meta`。修改前保留路由器侧备份；结构不符合 OpenClash `v0.47.156` 预期时停止并回滚。

## 4. ASN 数据库

旧 `openclash_geo.sh` 快照在 `geoasn` 分支直接 `return 0`，旧 `restore.ps1` 还会把 `ASN.mmdb` 链接到 `/dev/null`。

当前配置包含 `IP-ASN` 规则，Mihomo 实测会把这种文件判定为无效并重新下载。因此新恢复脚本保留有效的 `ASN.mmdb`，把它移动到 `/tmp/etc/openclash/ASN.mmdb`，再建立符号链接，不再阻断 ASN 数据库。

## 5. 完整配置

`openclash.config` 是完整现场备份，包含敏感信息。它只用于本机灾难恢复，并被 `.gitignore` 排除。普通恢复只写入六个脱敏字段；只有显式使用 `-RestorePrivateConfig` 才上传完整配置。
